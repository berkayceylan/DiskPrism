The disk map that fits in 612 KiB

DiskPrism is a native macOS disk space analyzer. It scans with getattrlistbulk, draws a cushion treemap or a sunburst with Metal, and goes completely quiet when you stop moving.

        Four decisions behind the numbers

        Ask the kernel for a whole directory at once

        getattrlistbulk returns names, sizes, dates, flags and link counts for a batch of entries in one call. A pool of work-stealing threads decodes each 128 KiB buffer with bounds checks and memcpy, because 8-byte fields sit on 4-byte boundaries.

        macOS gives / and /System/Volumes/Data the same device ID, so comparing st_dev would count your files twice. Three checks keep a scan on its volume:

        1. Mount status of each entry, from ATTR_DIR_MOUNTSTATUS
        2. Mount table, looked up before a directory is opened
        3. Device ID of every entry in the batch

        Keep the tree in one array

        Every file is a 56-byte record in one contiguous block of virtual memory, linked by 32-bit indices. Names live back to back in a string pool. Threads reserve space with a single atomic step and never invalidate each other's pointers.

        A parent always comes before its children, so adding up two million sizes is one backward pass. Deleting a file subtracts its size up the ancestor chain and the map updates without a rescan.

        Count what is really on the disk

        A file's length says little about the space it takes. DiskPrism reads the allocated blocks and treats four cases separately. The scan threads run under an I/O policy that forbids downloading cloud files, and cloud-only folders are never opened.

        Draw everything in one call

        Each block carries the coefficients of its cushion: a parabola per nesting level, summed. The fragment shader derives the surface normal from them, so shading needs no textures and no geometry beyond four vertices. The sunburst computes exact polar distances for smooth edges.

        The shader ships as text and compiles at launch with newLibraryWithSource:, so building needs only the Command Line Tools.

        [encoder drawPrimitives:MTLPrimitiveTypeTriangleStrip
            vertexStart:0
            vertexCount:4
          instanceCount:47841];

        Build from source

        You need macOS 14 or later, CMake 3.24 or later, and the Command Line Tools (xcode-select --install). Xcode is not required.

        Get the code

        git clone https://github.com/berkayceylan/DiskPrism.git
        cd DiskPrism

        Build

        cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
        cmake --build build -j

        Launch

        open build/DiskPrism.app

        Benchmark your Mac

        build/DiskPrism.app/Contents/MacOS/DiskPrism --benchmark /Applications --runs 5

        Run the tests

        ctest --test-dir build --output-on-failure

        Signing

        The build signs the app ad hoc, on your own Mac. An app you build yourself opens normally. If you copy it to another Mac, Gatekeeper will ask for confirmation there.

        Full Disk Access

        DiskPrism works without it. macOS then hides some protected folders, and the app tells you how many it skipped. If you grant it, macOS ties the permission to that build and may ask again after you rebuild.

        If the C++ headers are missing

        Some Command Line Tools updates leave a stale usr/include/c++ folder behind that hides the real headers. CMake detects this, warns, and builds against the SDK's headers.
